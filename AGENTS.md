# AGENTS.md

## Big Picture Architecture
- `app/` is the composition root: navigation, DI, networking, and screen orchestration live here (see `app/src/main/java/com/vonage/android/navigation/AppNavHost.kt`, `app/src/main/java/com/vonage/android/di/*.kt`).
- `vonage-video-core/` wraps the Vonage/OpenTok SDK behind `VonageVideoClient` + `CallFacade` abstractions (`vonage-video-core/src/main/java/com/vonage/android/kotlin/VonageVideoClient.kt`).
- `vonage-video-ui-compose/` owns reusable Compose UI and generated theme code (`vonage-video-ui-compose/build.gradle.kts`, `src/main/java/com/vonage/android/compose/theme`).
- Feature modules (`vonage-feature-*`) are optional capabilities wired through module boundaries and DI, not ad-hoc flags in `app`.
- Shared utilities live in `vonage-video-shared/`; logging pipeline is isolated in `vonage-android-logger/`.

## Config-Driven Behavior (Critical)
- Treat `config/app-config.json` as the source of truth for feature behavior and backend URL placeholders (`${BASE_API_URL}`).
- Never hand-edit `gradle/generated-config.properties`; it is generated by `generateVonageConfig` (`build-tools/gradle-config-plugin/.../GenerateConfigTask.kt`).
- `app/build.gradle.kts` maps generated properties to `BuildConfig` booleans and `missingDimensionStrategy(...)` per feature dimension (`chat`, `reactions`, `archiving`, etc.).
- Generated runtime constants are under package `com.vonage.android.config` as `AppConfig` (`build-tools/gradle-config-plugin/.../JsonConfigExtension.kt`).
- `generateVonageConfig` is wired as a dependency of Kotlin/KSP tasks in `app/build.gradle.kts`; config changes should be regenerated before builds/tests.

## Feature Toggle Pattern (Enabled/Disabled Variants)
- Optional modules use flavor dimensions with `enabled`/`disabled` product flavors (example: `vonage-feature-chat/build.gradle.kts`).
- Implement both flavor source sets when adding/changing a feature API (example pair: `vonage-feature-chat/src/enabled/.../ChatModule.kt` and `vonage-feature-chat/src/disabled/.../ChatModule.kt`).
- Keep public contracts in `src/main` and flavor-specific implementations in `src/enabled` + `src/disabled` (example: `vonage-feature-chat/src/main/java/com/vonage/android/chat/ChatFeature.kt`).

## Runtime Data Flows and Integration Points
- Backend session bootstrapping: `APIService.getSession()` -> `SessionRepository` -> `MeetingRoomScreenViewModel.connect(...)` -> `VonageVideoClient.initializeSession(...)`.
- `BASE_API_URL` is used in three places: Retrofit base URL (`RetrofitModule.kt`), deep links (`AppNavHost.kt`), and sharing links (`util/navigateToShare.kt`).
- DI is Hilt-based singleton wiring; plugin extension points are injected into core client (`SdkModule.provideVonageVideoClient(...)` passes chat/reaction `SignalPlugin`s).
- Networking adds custom UA headers via `VeraHeaderRequestDecorator` and debug-only HTTP logging (`RetrofitModule.kt`).

## Developer Workflows That Matter
- Initial setup after config edits: `./gradlew generateVonageConfig` (documented in `README.md` and `docs/CONFIG-SYSTEM.md`).
- Install local git hooks (pre-push runs detekt): `./gradlew installGitHooks` (`build.gradle.kts`, `scripts/git-hooks/pre-push`).
- Build/install app: `./gradlew installDebug`.
- Unit tests all modules: `./gradlew test`; module-only test example: `./gradlew :vonage-video-core:test`.
- Instrumented tests: `./gradlew connectedAndroidTest` or managed device: `./gradlew pixelDebugAndroidTest`.
- Public API compatibility check used in CI: `./gradlew apiCheck` (`.github/workflows/android.yml`).
- Coverage/reporting: `./gradlew koverHtmlReport` (Kover is centralized in root `build.gradle.kts` + `build-tools/kover.gradle`).
- Static analysis gate: `./gradlew detekt`; pre-push hook runs detekt (`scripts/git-hooks/pre-push`).

## Codebase-Specific Conventions
- Kotlin + Java 17 across modules (`app/build.gradle.kts`, feature module build files).
- Compose linting is strict through detekt compose rules (`build.gradle.kts` detekt plugin + `build-tools/detekt/detekt.yml` `Compose` section).
- Branching model in docs: contribute from `develop`, not `main` (`docs/CONTRIBUTING.md`).
- PR base-branch guard in CI: non-`release-*` branches must target `develop`; `release-*` branches target `main` (`.github/workflows/check-base-branch.yml`).
- Keep generated/theme outputs plugin-driven (`com.vonage.json-config`, `com.vonage.theme-generator`) instead of manual code edits.
